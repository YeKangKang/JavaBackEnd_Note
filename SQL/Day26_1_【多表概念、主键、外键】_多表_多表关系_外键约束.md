# Day26 · MySQL（多表、多表关系、外键约束）

## 1. 多表概述

在实际开发中，一张表难以覆盖所有业务需求。随着数据量增长或结构复杂度提升，使用**多表结构**可以避免数据冗余、提升一致性与查询效率。

---

## 2. 多表关系类型

MySQL 中常见的表与表之间的结构关系包括**一对多**，**多对多**，**一对一**：

### 2.1 一对多

主表的一个记录可关联从表的多条记录。从表通过外键字段引用主表主键实现。

**场景示例：** 一个部门对应多个员工。

- 主表：`department(id, name)`
- 从表：`employee(id, name, dept_id)`

> **`dept_id` 是从表中的外键字段**，用于引用主表 `department` 表的主键 `id`，建立两表之间的从属关系。

### 2.2 多对多

两个实体间彼此存在多重关联。需要创建中间表，记录两个主表主键的映射关系。

**场景示例：** 一个学生可选多门课程，一门课程也可被多个学生选择。

- 主表：`student(id, name)`
- 主表：`course(id, title)`
- 中间表：`student_course(student_id, course_id)`

> **`student_id` 和 `course_id` 是中间表中的外键字段**，分别引用 `student` 和 `course` 表的主键，用于记录学生与课程的多对多关联。

### 2.3 一对一

两张表的记录一一对应，从表外键引用主表主键，并加上 `UNIQUE` 限制。

**场景示例：** 一位用户只能绑定一个身份证号。

- 主表：`user(id, name)`
- 从表：`id_card(id, info, user_id)`

> **`user_id` 是从表中的外键字段**，引用主表 `user` 的主键 `id`，并加上 `UNIQUE` 约束，确保一位用户只能对应一个身份证，实现一对一关系。

---

## 3. 外键约束

### 3.1 主键（Primary Key）

主键用于唯一标识一条记录，必须非空且唯一。每张表只能有一个主键字段。

```sql
ALTER TABLE 表名 ADD PRIMARY KEY (字段名); -- 向字段添加主键特性
ALTER TABLE 表名 DROP PRIMARY KEY;         -- 删除主键特性
```

> 主键常作为其他表的外键引用目标。

---

### 3.2 外键（Foreign Key）

外键用于将当前表的字段与**另一张表的主键**建立关联，用于描述**多表关系**。

- 外键字段的值必须来自目标主表的主键，或为 `NULL`
- 一对一中应对外键加上 `UNIQUE` 限制
- 一对多、多对多场景中外键允许重复

```sql
ALTER TABLE 从表名
ADD [CONSTRAINT 外键约束名]
FOREIGN KEY (外键字段) REFERENCES 主表名(主键字段); -- 向字段添加外键特性

ALTER TABLE 从表名 DROP FOREIGN KEY 外键约束名; -- 删除外键特性
```

> 外键约束名不是字段名，仅用于命名该条外键规则。建议使用 `fk_当前表_目标表` 作为命名规范。

---

## ✅ 总结

- 多表结构能避免冗余，提升查询效率
- 表关系类型：一对多 / 多对多 / 一对一
- 外键约束通过字段引用建立多表关联
- 外键命名建议统一为：`fk_当前表_目标表`
