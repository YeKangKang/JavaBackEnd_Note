## 2. 网络通信基础

### 2.1 网络通信协议

- 网络通信依赖双方遵守统一协议（格式、速率、顺序等）
- 主流协议：TCP / IP

#### TCP / IP 四层模型

| 层级     | 描述                   | 示例协议                      |
|----------|------------------------|-------------------------------|
| 应用层   | 面向用户的服务         | HTTP, FTP, SMTP, DNS          |
| 传输层   | 端到端通信，可靠传输   | TCP, UDP                      |
| 网络层   | 路由、跨网段寻址       | IP, ICMP                      |
| 链路层   | 硬件通信，驱动层       | MAC, Wi-Fi, Ethernet          |

### 2.2 协议分类对比

| 协议 | 类型     | 是否可靠 | 是否连接 | 应用场景         | 限制或特点                   |
|------|----------|-----------|-----------|------------------|------------------------------|
| TCP  | 面向连接 | ✅         | 是        | 网页、文件传输   | 三次握手，慢但稳定           |
| UDP  | 无连接   | ❌         | 否        | 语音、视频传输   | 快速，最多 64KB，不保证到达 |

#### TCP 三次握手流程

1. 客户端发送 SYN 请求
2. 服务器回应 SYN+ACK
3. 客户端回应 ACK，连接建立

## 3. 网络通信三要素

### 3.1 协议
网络通信必须遵循统一的协议，才能确保双方能正确识别、解析并处理数据。协议规定了数据格式、传输顺序和控制方式。常见协议有 TCP、UDP、HTTP 等，通信双方必须使用相同协议才能正常交流。

### 3.2 IP 地址

IP（Internet Protocol）地址用于唯一标识网络中的每一台设备，相当于设备在网络中的“地址”。通信时，数据包需要通过目标 IP 才能正确送达。常见的有 IPv4 和 IPv6 两种格式。

| 类型   | 特征                                      |
|--------|-------------------------------------------|
| IPv4   | 32 位，常见格式如 `192.168.1.1`           |
| IPv6   | 128 位，格式如 `ABCD:EF01:...`            |

#### 常用命令
- `ipconfig / ifconfig`：查看本机 IP
- `ping IP`：测试网络连通
- `127.0.0.1` / `localhost`：回送地址（本机通信）

### 3.3 端口号
- 区分同一主机中不同程序，范围 0–65535
- 0–1023 为知名端口；1024 以上供用户程序使用
- 通信标识 = `协议 + IP + 端口`

## 4. Java 实现 TCP 通信

### 4.1 客户端：`Socket` 类

```java
public Socket(String host, int port)
```
- 创建并连接远程服务端（IP+端口）
- 若 `host` 为 `null`，则默认本机（回送地址）

#### 常用方法

| 方法                             | 说明                                   |
|----------------------------------|----------------------------------------|
| `getInputStream()`               | 获取字节输入流（接收数据）             |
| `getOutputStream()`              | 获取字节输出流（发送数据）             |
| `close()`                        | 关闭连接及相关流                      |
| `shutdownOutput()`              | 逻辑关闭写通道，发送 FIN               |

> `shutdownOutput()` 会逻辑关闭写通道，后续无法再发送数据；作用类似关闭输出流，但不会关闭整个连接。

### 4.2 服务端：`ServerSocket` 类

| 构造方法                             | 说明                             |
|--------------------------------------|----------------------------------|
| `public ServerSocket(int port)`      | 创建并绑定监听端口               |

#### 常用方法

| 方法             | 说明                                                 |
|------------------|------------------------------------------------------|
| `accept()`       | 阻塞监听连接，成功后返回一个 `Socket` 通信对象     |

> 注意：`accept()` 会阻塞主线程，需搭配多线程使用。

## 5. 基础消息通信案例

### 步骤流程：
1. 服务端启动 `ServerSocket`，调用 `accept()` 等待连接
2. 客户端启动 `Socket`，连接指定 IP+端口
3. 建立连接后，双方使用输入输出流通信

### 示例说明

- 客户端通过 `getOutputStream().write("hello".getBytes())` 发送消息
- 服务端通过 `getInputStream().read(byte[])` 读取数据并转为字符串
- 服务端通过 `getOutputStream().write()` 回发确认
- 客户端读取 `getInputStream()` 中的确认消息并打印

> 字节流读取需结合 `read()` 返回值判断读取长度，避免乱码或多读。

## 6. 文件 / 图片上传案例

### 6.1 步骤简述

1. 客户端：读取文件 → 通过 Socket 写给服务端
2. 服务端：接收数据 → 保存为新文件

### 推荐流结构：
- 客户端输入：`BufferedInputStream(FileInputStream)`
- 客户端输出：`BufferedOutputStream(Socket.getOutputStream())`
- 服务端输入：`BufferedInputStream(Socket.getInputStream())`
- 服务端输出：`BufferedOutputStream(FileOutputStream)`

> 文件是二进制数据，应使用字节缓冲流传输；字符流涉及编码表，容易导致乱码，效率也低。

### 常见优化

| 优化项               | 说明                                           |
| -------------------- | ---------------------------------------------- |
| 读写缓冲流           | 降低磁盘 IO、提高网络传输效率                  |
| 文件名自动生成       | 使用 `System.currentTimeMillis()` 防止覆盖文件 |
| 多线程处理多个客户端 | 每次 `accept()` 后用线程处理，主线程继续监听   |
| 防止 read 阻塞       | 合理设置传输结束条件：如关闭输出流，设定标志位 |

---

## ✅ 总结

- 网络通信依赖协议、IP、端口三要素，其中 TCP 是可靠的主流协议
- Java 使用 `Socket` 和 `ServerSocket` 类实现 TCP 通信
- `read()` 在网络通信中可能阻塞，需明确传输结束标志或关闭通道
- 文件传输需使用字节流，推荐搭配缓冲流提高效率
- 多线程服务端是构建高并发服务器的基础模型
