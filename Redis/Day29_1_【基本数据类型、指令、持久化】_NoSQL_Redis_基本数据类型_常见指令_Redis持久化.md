# Day29 · Redis基础（NoSQL、Redis、基本数据类型、常见指令、Redis持久化）

## 1. NoSQL 概述

**NoSQL（Not Only SQL）** 是非关系型数据库的统称。相较传统 SQL 数据库，在以下方面表现更优：

- 高并发读写
- 海量数据访问
- 灵活数据类型（无需建表）
- 高可用性（结构修改不会导致服务下线）
- 易扩展性（支持分布式横向扩展）

### 1.1 NoSQL vs SQL

| 项目       | SQL                         | NoSQL                               |
|------------|------------------------------|--------------------------------------|
| **数据结构** | 表、行、列                   | 键值、文档、列族、图                |
| **数据关联** | 强调表间关系（外键、多表）    | 无关联（依赖嵌套或业务逻辑处理）    |
| **查询方式** | SQL 查询语句                 | 命令/接口                            |
| **存储方式** | 磁盘 IO                      | 内存 IO                              |
| **扩展性** | 垂直扩展（受制于单机性能）   | 水平扩展（天然支持分布式）           |

> **SQL**：适用于强事务、高一致性业务场景。【结构化 + 关系化 + 强一致性】
> **NoSQL**：适用于缓存、大数据、高并发场景。【灵活 + 高性能 + 易扩展】

## 2. Redis 概述

**Redis（Remote Dictionary Server）** 是开源高性能**键值对结构 NoSQL 数据库**。常用于缓存、消息队列、session 管理、秒杀系统等**热点数据的存储**。

**核心特性：**

- 键值结构，`value` 支持多种数据类型
- 单线程，所有命令天然原子性
- 内存读写，无频繁磁盘 IO
- 支持持久化（RDB/AOF）
- 主从集群（从节点可以备份主节点整库，读写分离，整库容灾）
- 分片集群（数据按 slot 拆分存储，多主多从，slot 粒度容灾）

## 3. Redis 通用命令

| 命令                | 含义                         |
|---------------------|------------------------------|
| `DEL key [key...]`  | 删除一个或多个键              |
| `KEYS pattern`      | 模糊匹配键（慎用，生产环境易阻塞） |
| `TYPE key`          | 查看键的数据类型              |
| `EXISTS key`        | 判断键是否存在（0/1）         |
| `EXPIRE key seconds`| 设置键过期时间（单位：秒）    |
| `TTL key`           | 查看键剩余时间（-2已删，-1永久） |

## 4. Redis 基本数据类型

Redis 的 `Key` 为字符串类型，`Value` 支持五种数据类型：**字符串**、**哈希**、**列表**、**集合**、**有序集合**。

### 4.1 String（字符串）

Redis 中最基础的数据类型。

- 支持任意字节流
- 二进制安全（可以储存任意字符，包括乱码、不可见字符、`\0` 等）
- 支持数值运算命令（如 `INCR`、`DECR`），值在运算时会临时转为数字，结果仍以字符串形式存储。
- 单个值最大支持 512MB

| 命令                     | 含义                     |
| ------------------------ | ------------------------ |
| `SET key value`          | 设置键值对               |
| `GET key`                | 获取值                   |
| `MSET key1 value1 [...]` | 批量设置键值对           |
| `MGET key1 [...]`        | 批量获取值               |
| `INCR key`               | 整数 `value` 自增 1      |
| `INCRBY key n`           | 按整数增加值             |
| `INCRBYFLOAT key f`      | 按浮点数增加值           |
| `SETNX key value`        | 若键不存在则设置         |
| `SETEX key sec value`    | 设置键值对并指定过期时间 |

> Redis 底层会对整数使用整数编码，节省内存，对用户透明

---

### 4.2 Hash（哈希）

Hash 类型是一个**无序字典**，类似 Java 中的 `HashMap`，用于存储多个字段键值对。

- 值结构为 `field:value` 组成的集合（哈希结构）
- 每个哈希结构由一个外层 `key` 标识
- 内部字段数量可变，不同键可包含不同数量字段

| 命令                         | 含义                   |
| ---------------------------- | ---------------------- |
| `HSET key field value [...]` | 设置字段（支持多字段） |
| `HGET key field`             | 获取指定字段的值       |
| `HMGET key f1 f2 ...`        | 批量获取多个字段值     |
| `HDEL key field [...]`       | 删除一个或多个字段     |
| `HGETALL key`                | 获取所有字段和值       |
| `HKEYS key`                  | 获取所有字段名         |
| `HVALS key`                  | 获取所有字段值         |
| `HINCRBY key field n`        | 按整数增加字段对应的值 |
| `HSETNX key field value`     | 若字段不存在则设置     |

---

### 4.3 List（列表）

List 类型底层实现是一个**双向链表**，类似 Java 中的 `LinkedList`。

- 元素**有序**，**可重复**，支持正向和反向操作
- 插入与删除性能高
- 查询性能一般

| 命令                             | 含义                           |
|----------------------------------|--------------------------------|
| `LPUSH key value [...]`         | 从左侧插入元素（头部）         |
| `LPOP key`                      | 从左侧弹出元素                 |
| `RPUSH key value [...]`         | 从右侧插入元素（尾部）         |
| `RPOP key`                      | 从右侧弹出元素                 |
| `LRANGE key start end`          | 获取指定范围元素（0 -1 全范围） |
| `BLPOP key [...] timeout`       | 阻塞式左弹出，支持等待（秒）      |
| `BRPOP key [...] timeout`       | 阻塞式右弹出，支持等待（秒）      |

> List可以被当作**队列结构**（同进异出）或**栈结构**（同进同出）使用

---

### 4.4 Set（集合）

Set 类型类似 Java 中的 `HashSet`。

- 元素**无序**，**不可重复**
- 插入与删除性能高
- 底层基于哈希结构，查询性能高
- 支持集合运算操作

| 命令                     | 含义                      |
| ------------------------ | ------------------------- |
| `SADD key member [...]`  | 添加集合元素              |
| `SREM key member [...]`  | 移除集合元素              |
| `SCARD key`              | 获取集合元素个数          |
| `SISMEMBER key member`   | 判断元素是否存在          |
| `SMEMBERS key`           | 获取集合所有元素          |
| `SINTER key1 key2 [...]` | 求多个集合交集            |
| `SUNION key1 key2 [...]` | 求集合并集                |
| `SDIFF key1 key2 [...]`  | 求集合差集（key1 - key2） |

> 常用于**好友列表**、**标签系统**、**去重集合**等需保证元素唯一，并支持集合运算的场景。

---

### 4.5 SortedSet（有序集合）

Redis 中的有序集合类型（SortedSet）为集合中每个元素关联一个数值型分数（score），并默认按 score 升序排序。

- 元素**有序**，**不可重复**，按照 score 进行自动排序
- 插入与删除性能高
- 查找效率高
- 支持范围检索、权重排序、集合运算等操作

| 命令                                | 含义                           |
|-------------------------------------|--------------------------------|
| `ZADD key score member [...]`       | 添加成员并设置分数             |
| `ZREM key member [...]`             | 移除一个或多个成员             |
| `ZSCORE key member`                 | 获取成员的分数                 |
| `ZRANK key member`                  | 获取成员排名（升序）           |
| `ZCARD key`                         | 获取成员总数                   |
| `ZCOUNT key min max`               | 统计指定分数区间内的成员数     |
| `ZINCRBY key increment member`      | 增加成员的分数值               |
| `ZRANGE key start stop [WITHSCORES]`| 获取排名区间成员（升序）       |
| `ZRANGEBYSCORE key min max`         | 获取分数区间成员               |
| `ZINTER` / `ZUNION` / `ZDIFF` | 交集/并集/差集               |

> **默认按分数升序排序**，可使用 `REV` 类命令实现倒序（如 `ZREVRANK`，`ZREVRANGE`）。

## 5. Redis 持久化

Redis 的高性能依赖于内存存储机制。为保证数据不丢失，可通过**持久化机制将数据从内存保存到磁盘**。Redis 支持两种持久化方式：RDB 和 AOF，可单独或联合使用。

### 5.1 RDB（Redis Database）

- 默认启用，按配置周期性生成内存快照写入磁盘（.rdb 文件）
- 启动时如存在 RDB 文件，会自动加载恢复数据
- 持久化由子进程执行，避免阻塞主线程，适合大批量集中保存

### 5.2 AOF（Append Only File）

- 记录所有写命令日志，重启时可回放指令还原数据

- 采用追加写入（append）模式，确保断电也不会破坏现有数据

- 支持三种同步策略：每次写、每秒写、操作系统控制

> AOF 文件体积过大时会触发自动重写，以当前数据状态生成新日志文件压缩体积

## ✅ 总结

- Redis 是高性能、内存级别、键值对结构的 NoSQL 数据库
- 支持多种数据结构（String / Hash / List / Set / SortedSet）
- 所有操作具备原子性，适合高并发业务
- 提供 RDB 和 AOF 两种持久化机制
