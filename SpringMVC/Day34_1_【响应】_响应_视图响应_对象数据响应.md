# Day34 · Spring MVC（响应、视图响应、对象数据响应）

## 1. 响应概述

在 SpringMVC 中，**响应是服务器处理请求后返回给客户端的内容**，可能包括页面跳转、JSON 数据、文件流、状态码等。Controller 方法的响应行为由**返回值类型与是否使用注解（如 `@ResponseBody`）共同决定**。

常见响应方式：

- **视图响应**：返回 `String` 类型视图名，交由 **视图解析器** 拼接路径并跳转到对应页面资源
- **对象数据响应**：返回对象类型（如 POJO、集合），交由 **消息转换器** 自动序列化为 JSON 并写入响应体

> 通常返回值即为响应结果（`void` 除外）。大多数响应通过**视图解析器**或**消息转换器**处理，少数如文件下载、状态码设置等由控制器方法自行处理响应内容。

---

## 2. 视图响应

当 Controller 方法返回值为 `String`，且未加 `@ResponseBody`（即未指示用消息转换器处理）时，Spring MVC 默认将其视为**逻辑视图名**，交由视图解析器处理。

视图解析器会将逻辑视图名与其自身配置的 **前缀** 和 **后缀** 进行拼接，形成实际页面路径。

> **实际视图名** = 视图解析器前缀 + **逻辑视图名** + 视图解析器后缀

```java
@RequestMapping("/home")
public String home() {
    return "index"; // 由视图解析器拼接生成实际页面路径（如 /WEB-INF/views/index.jsp）
}
```

### 2.1 配置视图解析器

视图解析器属于 **SpringMVC 的组件**，用于拼接逻辑视图名为完整路径并跳转页面。一个 MVC 容器中可以注册多个视图解析器，SpringMVC 会按照优先级顺序依次调用，并使用第一个成功解析的视图资源。

常见视图解析器：

- `InternalResourceViewResolver`：拼接 JSP 路径
- `ThymeleafViewResolver`：用于 Thymeleaf 模板引擎

#### XML 配置方式（`spring-mvc.xml`）

```xml
<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
    <property name="prefix" value="/WEB-INF/views/" /> <!-- 前缀 -->
    <property name="suffix" value=".jsp" /> <!-- 后缀 -->
</bean>
```

#### 配置类方式（`SpringMvcConfig`）

```java
@Bean
public InternalResourceViewResolver viewResolver() {
    InternalResourceViewResolver resolver = new InternalResourceViewResolver();
    resolver.setPrefix("/WEB-INF/views/"); // 前缀
    resolver.setSuffix(".jsp");	// 后缀
    resolver.setOrder(0); // 数字越小，优先级越高
    return resolver;
}
```

> 在注册了多个视图解析器的情况下，可通过 `setOrder()` 方法控制优先级。

## 3. 对象数据响应（`@ResponseBody`）

当 Controller 方法返回对象（如 POJO、集合、数组等）作为数据响应时，应使用 `@ResponseBody` 注解，跳过视图解析器，交由 **消息转换器（HttpMessageConverter）** 自动序列化为 JSON 并写入响应体，前提是：

- **引入依赖**：如 `jackson-databind`

- **启用注解驱动**：`@EnableWebMvc` / `<mvc:annotation-driven />`

```java
@RequestMapping("/getPOJO")
@ResponseBody // 返回对象数据，自动序列化为 JSON
public User getPOJO() {
    return new User("Yuheng", 9999);
}
```

> `@RequestBody` 与 `@ResponseBody` 都会触发消息转换机制，用于对象与 JSON 的自动序列化 / 反序列化。

---

## ✅ 总结

- 控制器方法的返回值决定响应行为
- 返回 `String` 且未加注解 → 作为视图名交由视图解析器跳转页面
- 返回对象 + `@ResponseBody` → 自动序列化为 JSON，写入响应体
- 视图解析器控制页面跳转路径拼接，需注册 Bean 并设定前后缀
- 数据响应需引入 Jackson 并启用注解驱动配置
