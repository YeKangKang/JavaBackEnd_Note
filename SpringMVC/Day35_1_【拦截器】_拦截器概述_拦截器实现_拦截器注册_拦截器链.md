# Day35 · Spring MVC（拦截器概述、拦截器实现、拦截器注册、拦截器链）

## 1. 拦截器概述

拦截器（Interceptor）是**专用于拦截和增强 SpringMVC 控制器方法**调用的组件，可在**请求进入 Controller 前后插入逻辑，甚至中断执行流程**。（常用于登录验证、权限控制、访问统计等功能）

### 1.1 拦截器 vs 过滤器

| 对比点       | 拦截器（Interceptor）                        | 过滤器（Filter）                               |
| ------------ | -------------------------------------------- | ---------------------------------------------- |
| **执行位置** | DispatcherServlet 之后，专注 Controller 请求 | DispatcherServlet 之前，作用于所有请求         |
| **增强目标** | 拦截并增强 Controller 方法调用               | 请求增强、编码设置、请求头、状态码等非业务操作 |
| **使用场景** | 登录校验、权限验证、业务逻辑增强             | 编码统一、日志过滤、安全限制、CORS 跨域等      |

> **过滤器用于增强整个请求过程中的附加行为**，如编码、请求头等；**拦截器则专注于增强 Controller 方法执行过程**，聚焦具体业务操作。

## 2. 拦截器实现

自定义拦截器**需实现 `HandlerInterceptor` 接口，重写其三个生命周期方法**，并将该类**注册为 SpringMVC 容器中的 Bean**（通常与 Controller 同属扫描路径）。

- **`preHandle`：Controller 执行前调用**
  - **返回 `true`** → 执行 Controller 与后续操作
  - **返回 `false`** → 阻止 Controller 执行，后续操作全部跳过
- **`postHandle`：Controller 执行后、视图渲染前调用**
- **`afterCompletion`：请求全部处理完成后调用（资源清理、日志记录等）**

```java
@Component // 注册为 Bean
public class ProjectInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        // Controller 前置逻辑
        return true;
    }

    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response, Object handler, ModelAndView modelAndView) throws Exception {
        // Controller 后置逻辑（视图渲染前）
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response, Object handler, Exception ex) throws Exception {
        // 完成前逻辑（资源释放、异常处理等）
    }
}
```

> 所有**方法参数均为 Servlet 原生对象**，可直接进行状态控制、权限校验等处理。

## 3. 注册拦截器

实现拦截器后，可通过 **Spring MVC 配置类注册拦截器实例**。通常做法是让**配置类实现 `WebMvcConfigurer` 接口，并重写其 `addInterceptors()` 方法**。

在 MVC 启动时注入拦截器 Bean。多个拦截器将作为多个 Bean 实例被注册，并可分别配置各自的拦截路径。

```java
@Configuration
@EnableWebMvc
@ComponentScan({"org.example.controller"}) // 拦截器通常与 Controller 放在同一包内，若不在此包下需显式扫描
public class SpringMvcConfig implements WebMvcConfigurer {

    @Autowired
    private ProjectInterceptor interceptor; // 注入拦截器实例

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(interceptor)
                .addPathPatterns("/users", "/users/*"); // 配置拦截路径，可添加多个 URI
      	// 若有其他拦截器，可继续添加 registry.addInterceptor
    }
}
```

- **`addInterceptors(拦截器对象)`**：用于注册拦截器实例与作用路径
- **`addPathPatterns(...)`**：设置拦截 URI，可配置多个

> 推荐继承 `WebMvcConfigurer` 接口，避免继承 `WebMvcConfigurationSupport` 类导致自动配置失效

## 4. 拦截器链执行顺序

多个拦截器按顺序注册后，请求将依次经过它们组成的拦截器链，执行顺序遵循 **“前置正序、后置逆序”** 模型，**符合责任链设计模式**。

- **`preHandle`：**按注册顺序**正序**执行 `A → B → C`
- **`postHandle`：**按注册顺序**逆序**执行 `C → B → A`
- **`afterCompletion`：**按注册顺序**逆序**执行 `C → B → A`

### 4.1 责任链示例

下表拦截器按 A → B → C 顺序注册，且 B 的 `preHandle()` 返回 `false`，中断请求流程。

| 拦截器 | preHandle()                      | Controller | postHandle() | afterCompletion() |
| ------ | -------------------------------- | ---------- | ------------ | ----------------- |
| A      | ✔️ **第一个**执行                 | ❌ 不进入   | ❌ 不执行     | ✔️ **第二个**执行  |
| B      | ✔️ **第二个**执行（返回 `false`） |            |              | ✔️ **第一个**执行  |
| C      | ❌ 不执行（跳过）                 |            |              | ❌ 不执行          |

> 实际开发中通常只配置一个拦截器，拦截器链使用场景较少。

---

## ✅ 总结

- 拦截器可增强 Controller 方法调用过程，常用于登录权限、业务增强等场景
- 与过滤器区别：拦截器关注 Controller 方法，过滤器作用于整个请求
- 实现方式：自定义类实现 `HandlerInterceptor` 并重写三个生命周期方法
- 配置方式：通过实现 `WebMvcConfigurer` 并注册到 `addInterceptors()` 中
- 多拦截器形成责任链：前置正序、后置逆序、完成逆序
