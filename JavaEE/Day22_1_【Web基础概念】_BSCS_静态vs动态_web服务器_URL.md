# Day22 · JavaEE（BS/CS、静态vs动态、web服务器、URL）

---

## 1. B/S 与 C/S 架构对比

#### ✅ C/S（Client / Server）架构

- 客户端通常为桌面应用程序，直接与服务器通信
- 更依赖客户端能力与资源，部署成本较高

#### ✅ B/S（Browser / Server）架构

Web 编程采用 B/S 通信模式，通过浏览器访问服务器资源：

- 浏览器通过 URL 向服务器发送 HTTP 请求（request）
- 服务器响应请求，返回所需资源（response）
- 使用的协议为 HTTP（超文本传输协议）

> 实质上 B/S 架构仍是 C/S 架构的延伸，其底层通信依然基于 TCP/UDP 协议


## 2. Web 资源（动态 vs 静态）

Web 资源按响应方式可分为静态资源、动态资源：

- 静态资源：直接存储在服务器中，请求时**原样返回**，不经过程序逻辑处理【`.html`、`.css`、`.js`、图片、视频等】

- 动态资源：每次请求由服务器**动态生成内容**，通常涉及后端逻辑与数据库交互【`.jsp`、Servlet、ASP、PHP 等】


## 3. Web 服务器

Web 服务器（Web Server）是指能够接收来自浏览器的 HTTP 请求，并将网页资源（包括静态和动态内容）响应给客户端的软件系统。它对 JavaEE（J2EE）规范中的部分接口进行了实现，开发者可以基于这些标准接口快速设计和构建 Web 后端程序。

- **`Tomcat`**：轻量级服务器，支持 Servlet 和 JSP 规范；
- `WebLogic`、`WebSphere`、`JBoss`：支持完整 JavaEE 企业级规范，适用于大型项目部署。


## 4. URL 基本结构

URL（Uniform Resource Locator，统一资源定位符）用于唯一表示互联网上的资源位置。

#### URL 完整格式

```
协议://域名:端口号/资源路径?参数=值
```

- **`协议`**：资源传输所使用的协议，如 HTTP、HTTPS、FTP 等
- **`域名/IP`**：服务器的网络地址（如 `google.com`），由 DNS 解析为 IP
- **`端口号`**：通信端口，HTTP 默认为 80，可自定义如 8080、8000 等
- **`资源路径`**：服务器上的资源位置，通常为相对路径（如 `/page/login.html`）
- **`?参数=值`**：客户端传递给服务器的参数，常用于表单提交、查询等（如 `?name=Tom`）

> 浏览器访问的是 URL，但只有其中的“域名”部分会被 DNS 解析为 IP 地址


## ✅ 总结

- B/S 架构是 Web 应用的基本通信模型，本质仍基于 C/S 与 TCP 协议
- Web 资源分为静态（原样返回）与动态（逻辑处理后生成）两类
- Web 服务器如 Tomcat 是 Web 项目的运行容器，实现了部分 JavaEE 规范
- URL 用于唯一定位互联网上的资源，其结构中只有“域名”会被解析为 IP
