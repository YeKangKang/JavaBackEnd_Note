# Day32 · Spring AOP（AOP概述、原理及代理机制、AOP术语、AOP开发流程、切点表达式、通知类型、基于XML的AOP、基于注解的AOP）

## 1. AOP 概述

AOP（Aspect-Oriented Programming，面向切面编程）是一种用于**将横切关注点（如日志、事务、安全等）从业务逻辑中抽离**的编程思想。

它是对 OOP 的增强机制，能够在**不修改原有代码的前提下**，通过动态代理机制在运行时将增强逻辑**织入目标方法**，从而实现模块间的**松耦合与统一维护**。

---

## 2. Spring AOP 原理 & 代理机制

### 2.1 Spring AOP 原理

Spring AOP 的增强逻辑是通过**动态代理机制**实现的。

在目标方法执行前，Spring 会根据配置生成代理对象，**拦截方法调用**并在调用链中**织入增强逻辑**，实现对原有代码的无侵入扩展。

> **执行流程：** 所有前置通知（如有） → 目标方法 → 所有后置通知（如有）

### 2.2 Spring 动态代理选择机制（JDK vs CGLIB）

Spring 会根据**目标类是否实现接口**，自动选择代理方式以生成动态代理对象并织入增强逻辑：

- **JDK 动态代理**：若目标类**实现了接口**，则使用 JDK 的接口代理方式。底层通过 `Proxy.newProxyInstance()` 创建代理对象，增强逻辑通过重写 `invoke()` 方法注入。
- **CGLIB 动态代理**：若目标类**未实现接口**，则使用 CGLIB 的继承代理方式。底层通过 `Enhancer` 动态生成目标类的子类，在子类方法中包裹原方法并添加增强逻辑。

## 3. AOP 核心术语

| 术语        | 含义                                                         |
|------------|--------------------------------------------------------------|
| **`Target`**（目标对象） | 被增强的原始对象，包含业务逻辑                              |
| **`Proxy`**（代理对象） | Spring 织入增强逻辑后生成的动态代理对象**（用于替代目标对象）** |
| **`JoinPoint`**（连接点） | 程序运行中可插入增强逻辑的点**（Spring AOP 中为方法调用）** |
| **`Pointcut`**（切点） | 用于匹配哪些连接点需要被增强**（通常使用表达式）** |
| **`Advice`**（通知 / 增强） | 具体的增强逻辑**（前置/后置/环绕/异常/最终）** |
| **`Aspect`**（切面） | 通知 + 切点的组合，代表增强逻辑的模块化封装**（切面类）** |
| **`Weaving`**（织入） | 将增强逻辑织入目标对象的过程 |

> Spring AOP 在**运行期**通过动态代理完成织入；而 AspectJ 支持在**编译期或类加载期**进行静态织入。

---

## 4. AOP 开发流程

Spring AOP 的使用包括以下四个关键步骤：

1. **导入依赖**：引入 `spring-aop` 与 `aspectjweaver`，后者用于增强兼容性与底层织入能力。
2. **编写业务类**：定义包含核心业务逻辑的方法，这些方法天然构成 AOP 的连接点（JoinPoint），<u>由 Spring 管理为 Bean</u>。
3. **编写切面类**：编写用于封装增强逻辑的类（Aspect），<u>切面类本身也应作为 Bean 交由容器管理</u>。内部包含多个通知方法（Advice）。
4. **配置织入关系**：通过 XML 或注解方式绑定切点与通知，声明哪些方法应被增强、何时增强、增强逻辑为何。

## 5. 基于XML的AOP开发

在 XML 配置方式中，Spring AOP 通过 `<aop:config>` 标签统一声明切面、切点与通知之间的绑定关系。**在使用这些标签前，需在配置文件中引入 AOP 命名空间与约束路径。**

```xml
<aop:config>	<!-- 需要引入 AOP 命名空间 + 约束路径 -->
    <aop:pointcut id="切点 ID" expression="切点表达式"/>
    <aop:aspect ref="切面类的 Bean 名称">
        <aop:通知类型 method="通知方法名（定义在切面类中）" pointcut-ref="切点 ID"/>
        <aop:通知类型 method="通知方法名（定义在切面类中）" pointcut="切点表达式"/>
    </aop:aspect>
</aop:config>
```

- **`<aop:config>`：** 声明整个 AOP 织入逻辑的配置范围
- **`<aop:pointcut>`：** 抽取切点表达式，便于多处复用（全局 / 局部）
- **`<aop:aspect>`：** 定义切面类，内部包含该类中增强方法与切点的绑定关系集合
- **`<aop:通知类型>`：** 指定某个增强方法与切点的绑定关系（如 `<aop:before>`）

## 6. 切点表达式

### 6.1 基本语法

切点表达式用于定义哪些方法需要被 AOP 增强。Spring 会根据表达式筛选出所有符合条件的方法，将其作为**切入点（Pointcut）**。

```java
execution([访问修饰符] 返回值类型 包名.类名.方法名(参数列表))

execution(public void com.example.service.Target.method())	// 精确匹配某个方法
execution(void com.example.service.Target.*(..))						// 某类中所有返回值为 void 的方法
execution(* com.example.service.*.*(..))										// 指定包下所有类的所有方法
execution(* com.example.service..*.*(..))										// 指定包及其子包下所有类的所有方法
execution(* *..*.*(..))																			// 全局匹配
```

- **访问修饰符**：可省略，不影响表达式匹配效果。

- **返回值类型、包名、类名、方法名**：可以使用通配符 `*` 模糊匹配
- **包名与类名的匹配规则**：`.` 表示当前包下的类，`..` 表示当前包及其所有子包下的类。
- **参数列表**：`()` 表示无参方法，`(..)` 表示任意类型任意数量的参数，`(String, ..)` 表示以 String 开头的参数组合。

### 6.2 切点表达式抽取（XML）

在 XML 配置中，切点表达式可以通过 `<aop:pointcut>` 抽取为独立定义，便于在多个通知中复用。

- **全局切点**：定义在 `<aop:aspect>` 标签外，可被任意切面引用
- **局部切点**：定义在 `<aop:aspect>` 标签内，仅当前切面可见

```java
<aop:pointcut id="切点 ID" expression="execution(* com.example.service..*.*(..))"/>
```

## 7. 通知类型（XML）

**通知类型用于指定增强逻辑在切点方法的哪个阶段执行**。多个相同或不同的通知方法可同时作用于一个切点，按 XML 配置顺序依次织入。

| 通知类型         | XML 标签             | 执行时机                             |
|------------------|----------------------|------------------------------------------|
| **前置通知**     | **`<aop:before>`**    | 切点方法执行前                           |
| **后置通知**     | **`<aop:after-returning>`** | 切点方法正常返回后                         |
| **环绕通知**     | **`<aop:around>`**    | 包裹切点方法。可控制切点是否执行、返回值等 |
| **异常抛出通知** | **`<aop:after-throwing>`** | 切点方法抛异常时执行                       |
| **最终通知**     | **`<aop:after>`**     | 切点方法结束后始终执行（不论是否异常） |

#### 例：环绕通知

环绕通知是功能最强的通知类型，它**包裹并控制整个切点方法的执行流程**，不仅能在前后插入逻辑，还可以决定是否执行切点方法，以及如何处理其返回值。

```xml
<aop:通知类型 method="通知方法名" pointcut="切点表达式"/>         <!-- 直接绑定表达式 -->
<aop:通知类型 method="通知方法名" pointcut-ref="切点 ID"/>       <!-- 引用抽取的切点 -->
```

```java
// ProceedingJoinPoint 是对切点方法的封装对象
public Object around(ProceedingJoinPoint pjp) throws Throwable {
    System.out.println("前置逻辑");
    Object result = pjp.proceed(); // 调用目标方法
    System.out.println("后置逻辑");
    return result; // 返回切点方法的执行结果
}
```

## 8. 启用AOP注解支持 & 组件扫描（注解 AOP 开发）

使用注解方式前，**必须开启 Spring AOP 注解支持**，以便让 Spring 能够识别 `@Aspect` 等相关注解。同时，如果通过注解方式注册 Bean（如使用 `@Component`），还需开启 **组件扫描功能**。

- **启用 AOP 注解支持**
  - XML 配置：`<aop:aspectj-autoproxy/>`
  - Java 配置：`@EnableAspectJAutoProxy`
- **启用组件扫描**
  - XML 配置：`<context:component-scan base-package="要扫描的包"/>`
  - Java 配置：`@ComponentScan("要扫描的包")`

## 9. 基于注解的 AOP 开发

在注解方式中，AOP 的大部分配置集中在**切面类中**，通过注解完成切点定义与增强逻辑的绑定。**切面类必须注册为 Bean**，以便被 Spring 容器识别并织入。

```java
@Aspect
@Component
public class MyAspect {
    @Pointcut("切点表达式") // 抽取切点
    public void myPointcut() {}

    @通知类型("myPointcut()") // 绑定切点方法
    public void beforeAdvice() { ... }

    @通知类型("MyAspect.myPointcut()") // 内部类中使用外部切点
    public void beforeAdviceAlt() { ... }

    @通知类型("切点表达式") // 直接绑定表达式
    public void afterAdvice() { ... }
}
```

- **`@Aspect`**：标记当前类为切面类，其内部方法用于增强逻辑（通知）
- **`@Pointcut`**：将切点表达式抽取为空方法，便于复用与统一维护
- **`@通知类型`**：绑定通知方法与切点（切点表达式 / 切点抽取方法）

## 10. 切点表达式抽取（注解）

注解方式使用 `@Pointcut("表达式")` 声明切点表达式，**必须依附一个空方法**作为宿主。该方法仅用于标识切点，**本身不包含任何逻辑，也不会被执行**。

```java
@Pointcut("切点表达式")
public void logPointcut() {}  // 空方法，仅用于标识
```

- 方法必须为 `public void`，**无参数、无方法体**
- **`@Pointcut` 只在当前类中可见**，不支持全局复用（与 XML 不同）

> 💡 **补充**：除了使用表达式抽取切点，也可通过自定义注解方式进行切点控制。
>
> 例如**使用 `@AutoFill(OperationType.INSERT)` 手动标记目标方法**，并在切面中通过 `@annotation(...)` 捕获该注解，既可作为切点标识，又可携带元数据用于业务判断。

## 11. 通知类型（注解）

| 通知类型         | 注解             | 执行时机说明                                |
|------------------|------------------|---------------------------------------------|
| 前置通知         | `@Before`         | 切点方法执行前                              |
| 后置通知         | `@AfterReturning` | 切点方法正常返回后                          |
| 环绕通知         | `@Around`         | 包裹切点方法，控制是否执行与返回值          |
| 异常通知         | `@AfterThrowing`  | 切点方法抛出异常时                          |
| 最终通知         | `@After`          | 切点方法结束后始终执行（无论是否异常）      |

---

## ✅ 总结

- **AOP** 实现横切逻辑的分离，提升代码可维护性和复用性。
- **动态代理机制**是 Spring AOP 的核心（JDK 或 CGLIB）。
- **核心术语**：切点（Pointcut）、通知（Advice）、切面（Aspect）等。
- **开发方式**：支持 XML 与注解方式配置切面与通知关系。
- **表达式配置**支持通配符与抽取复用，简化配置复杂度。
- **环绕通知**功能最强，可控制切点执行与返回值。
